# 淡化表達的是「按下隱藏就會消失」,不是事實

分支的灰字**只**綁定 hidable branch —— merged 或 inactive,且不在豁免名單上(head、目前被篩選選取的、符合 `alwaysShow` 樣式的)。事實層則由另外的管道表達:merged 掛 `✓` badge,inactive 顯示年齡標籤,而且**即使該分支被豁免也照標**。

因此 `classifyMerged()` 與 `classifyInactive()` 各回傳兩個集合(事實 / hidable),而不是一個。

## 為什麼未來的讀者會困惑

兩個函式各回一組 pair,第一直覺是「這重複了,合併成單一集合就好」。合併掉會同時弄壞兩件事:

- **當前分支會變灰。** 你 checkout 在一個已合併的分支上時,`✓` 消失或整列變灰,兩種都不對 —— 灰的意思是「不用管了」,而當前分支永遠要管。「你還站在一個已合併的分支上」是這個功能最具行動價值的單一訊號。
- **淡化的意義會漂移。** 綁在 hidable 上時,灰字精確對應「按下隱藏開關,這些會不見」,使用者可以直接預測後果。綁在事實上時,灰字與開關的關係就斷了。

## 後果

- `BranchTreeLeaf` 上是三個獨立的布林 —— `isMerged`、`isInactive`、`isHidable` —— 不是一個列舉。它們正交,一列可以同時是灰的、帶 `✓`、又帶年齡。
- 年齡標籤的行為因此**改變**了:先前只給會被藏的分支,現在所有逾期分支都給,包含 `main` 與當前分支。
- head 那一列會同時出現左側的 check 圖示與右側的 `✓` badge。兩個勾意義不同(一個是「你在這」,一個是「已合併」),這是接受了的取捨 —— 換掉圖示會讓「我現在在哪個分支」失去一眼可掃視的線索。
- 圖形面板也綁 hidable,即使它自己不隱藏任何東西。判準必須跨面板一致 —— `develop` 這種在 `alwaysShow` 名單裡的已合併分支,若圖形照事實淡化、側檢視照豁免不淡化,同一個分支在兩個面板上會給出相反的答案。
- 因此豁免是在 extension host 算完才送進 webview(`dimmedBranches`),webview 只做查表。把豁免規則(尤其 glob 比對)複製一份到 webview 正是兩邊漂移的起點。
