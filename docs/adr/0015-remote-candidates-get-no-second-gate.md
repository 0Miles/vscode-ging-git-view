# 遠端候選與本地同等,且刻意不補第二道閘

清理對話框把遠端分支與本地分支**同等對待** —— 一起列出(分開分組)、同一套預設勾選(merged ∪ redundant)。遠端刪除因此少了本地才有的那道安全網,而我們**刻意不補**一個替代品。

## 為什麼未來的讀者會困惑

同一個對話框裡有兩種安全性,而 UI 上分不出來:

- **本地**的 redundant 分支第一輪必定失敗(`git branch -d` 擋下未完全合併的),被收集起來,由 batch run 用一個對話框問要不要強制刪除。git 自己把「有保證」和「需要強制」分開了。
- **遠端**沒有這回事。`deleteRemoteBranch` 是 `git push <remote> --delete <branch>`(`src/backend/actions/branch.ts`),**沒有任何 not-fully-merged 的把關**,叫下去就沒了。

於是「預設勾選裡含 redundant」這件事,對本地是「會再問你一次」,對遠端是「直接生效」。讀者看到這個落差,很容易以為遠端那條路漏了一道檢查沒寫。

它沒漏。這個不對稱是 git 的,不是我們造的,而我們手上**沒有任何 git 層面的東西**可以拿來當遠端的第二道閘。硬補一道,只能補一個心理上的 —— 而那比沒有更糟:多按一次「你確定嗎」會讓使用者以為系統對這件事有把握、有退路,實際上一個都沒有。

## 考慮過但否決的方案

**候選只列本地分支,遠端全交給下游確認框的「同時刪除遠端」。** 最安全,而且那條路已經存在、已經對選取集裡對應的 remote 節點做過去重。否決原因是它只涵蓋**有本地對應的**遠端分支:同事 squash merge 完就沒再管的 `origin/feature/foo`,你機器上從來沒有本地分支 —— 它永遠進不了那條路。而團隊 repo 裡的爛攤子,大半是這一種。

**遠端的 redundant 預設不勾(本地勾、遠端不勾)。** 直接對準風險。否決原因是同一個清單裡兩套勾選規則,而列與列之間看不出差別;使用者學到的規則會是錯的。

**給遠端刪除再加一輪確認。** 對話框變三段,而第二次問的內容跟第一次一模一樣 —— 使用者會直接點過去,同時被暗示這件事有退路。

## 後果

- **force 回合從安全網變成常態。** 預設勾選是 merged ∪ redundant,而 redundant 不保證 `git branch -d` 放行,所以典型的一次清理就是「第一輪過掉 merged,第二輪問 redundant 要不要強制」。看到 force 對話框每次都跳,不是 bug。
- **緩解手段只有三個,而且都是緩解,不是消除**:第一道確認框把 local 與 remote **分開列出**;候選逐列標明帶哪些事實(merged / redundant / inactive);對話框提供「fetch 後重算」。
- **「fetch 後重算」不只是求新,它會清掉一整類假候選。** ADR-0012 讓 fetch 預設 prune 已刪除的遠端追蹤分支,所以 fetch 一次,「遠端其實早就沒了、只剩本地幽靈追蹤 ref」的那些會自己消失。不 fetch 的話它們會列在清單上,而對它們按刪除會走進 `deleteRemoteBranch` 那條「遠端已經不在了,改成 prune 追蹤 ref」的補救路徑。
- **不自動 fetch。** 使用者只想看一眼有什麼可清,不該因此被要求輸入認證(askpass)。代價是他可能不按就直接刪,所以比對基準與其最後更新時間就寫在對話框上,和 ADR-0006 為 #11 記下的做法一致。
- **`inactive` 這個事實用在遠端分支上,意思會變。** 遠端追蹤 ref 的日期是「上次 fetch 到的那個 commit 的時間」,不是遠端當下的狀態;而一條長年沒動的遠端分支很可能是**別人的**工作,刪掉是從共用遠端上抹掉他的東西。merged / redundant 至少還能宣稱「內容已在主線」,inactive 什麼都沒宣稱。這個風險在決策時被提出並權衡過,擋住它的唯一機制是 inactive **從不參與預設勾選**。
- **「顯示遠端分支」關閉時,遠端不納入候選 —— 但要明講。** `branchFacts` 的 git 讀取以 `resolveShowRemote(repo)` 為參數,關掉時 snapshot 裡沒有遠端 ref。沿用這個開關(一個顯示開關不該偷偷擴大一個不可逆動作的範圍),但對話框必須寫出「遠端分支目前隱藏,未納入候選」,不能讓這個洞靜默存在。
- **偵測不到 default branch 時,merged 與 redundant 兩者都不可判定**(`CONTEXT.md`:default branch 是兩者的唯一基準),清單只剩 inactive、預設一條都不勾、深度檢查鈕停用。這裡**據實回報、不靜默** —— 對話框是使用者叫出來的隨選查詢,照 `CONTEXT.md` 的約定,靜默停用只適用於被動的顯示與隱藏。
